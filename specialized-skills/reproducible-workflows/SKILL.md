# Reproducible Workflows

## Workflow

1. Lay out the project with raw data kept read-only, derived data generated by code, scripts or notebooks under version control, and results traceable to the commands that produced them.
2. Pin environments: use a lockfile or exact versions (conda environment export, `requirements` with hashes, renv lockfile), or a container image referenced by digest rather than a mutable tag.
3. Control randomness by setting and recording seeds for stochastic steps, and note where results depend on hardware or thread count.
4. Use a workflow manager for multi-step pipelines so inputs, outputs, and parameters are declared. Keep parameters in a config file rather than editing code, and keep one entry point.
5. Checksum inputs and key outputs. Record reference genome and database versions as inputs, not assumptions.
6. Capture a provenance snapshot at run time:
   `python3 specialized-skills/reproducible-workflows/scripts/snapshot_env.py --inputs data/counts.csv data/meta.csv --output provenance.json`
   It records interpreter, platform, installed packages, git commit, and sha256 of inputs.
7. Test the pipeline on a small dataset, and rerun from a clean checkout or fresh container to confirm it works without hidden state.
8. Do not commit secrets, patient-level data, or large binaries. Reference controlled data by accession and access procedure.
9. Archive the release (tagged code, environment, and data pointers) in a repository that issues a persistent identifier when sharing publicly.

## Deliverable

A README with exact run commands, the lockfile or container reference, the provenance file, and a short note on expected run time and resources. State clearly any step that cannot be reproduced and why.
